Guide pillar · Claude Code en 2026

Claude Code,
le guide complet.

Salut, moi c'est Jérémy. Je ne suis ni développeur ni codeur — je suis un entrepreneur qui utilise Claude Code tous les jours. Ici, je rassemble tout ce que tu dois savoir : ce que c'est, pourquoi ça change la donne, comment ça se compare à Cursor ou Codex, comment l'installer, et les workflows qui m'ont vraiment servi.

20 min pour l'installer 37 skills à dispo 140+ plugins officiels 1 M tokens de contexte
— Définition

Qu'est-ce que
Claude Code ?

En une phrase

Claude Code est un outil en ligne de commande créé par Anthropic, qui transforme l'IA Claude en agent capable de lire, écrire et exécuter du code directement sur ton ordinateur. Au lieu de copier-coller du code depuis un chat, tu lui parles en français, et il agit dans tes fichiers, lance des scripts, lit ton codebase, teste, corrige.

Concrètement, Claude Code, c'est la version terminal de Claude. Tu ouvres ton terminal, tu tapes claude, et tu te retrouves dans une session interactive où l'IA peut faire ce qu'un assistant humain ferait à ta place : ouvrir un fichier, le modifier, lancer un test, valider, recommencer. Tu peux lui dire « Ajoute un formulaire d'inscription à ma page, connecte-le à Resend, teste que ça marche », et il enchaîne les étapes tout seul.

Claude Code vs Claude.ai (le chat)

Claude.ai, c'est la conversation — tu poses des questions, Claude répond du texte. Claude Code, c'est l'exécution — tu donnes une intention, Claude lit ton projet, manipule des fichiers, exécute des commandes shell, et te livre un résultat. C'est la même IA derrière (les modèles Sonnet et Opus d'Anthropic), mais l'interface change tout. Sur Claude.ai tu copies-colles du code à la main ; avec Claude Code tu ne touches plus jamais à un clavier de programmation.

Claude Code vs Cursor, Aider, Codex et GitHub Copilot

Tous ces outils utilisent une IA pour écrire du code. La différence se joue sur trois axes : où ça vit (terminal vs éditeur), qui agit (toi vs l'agent), et le modèle derrière (Claude vs GPT vs autres). Cursor est un éditeur de code complet avec un chat ; Aider est un CLI open-source qui modifie des fichiers ; GitHub Copilot est un autocomplete intégré dans VS Code ; Codex est l'agent CLI d'OpenAI. Claude Code combine la simplicité d'Aider, l'agentivité de Codex, et la qualité de raisonnement de Claude.

Tu trouveras le tableau de comparaison détaillé un peu plus bas sur cette page. Si tu veux le résumé : prends Cursor si tu veux remplacer VS Code, prends Claude Code si tu veux déléguer des tâches entières à un agent autonome.

Pour qui c'est fait ?

Officiellement, c'est un outil pour développeurs. Dans les faits, j'utilise Claude Code tous les jours sans être développeur. Si tu sais ouvrir un terminal et copier-coller une commande, tu peux l'utiliser. Je connais des consultants qui s'en servent pour générer des rapports clients, des marketeurs qui montent leurs landing pages sans dev, des avocats qui automatisent la relecture de contrats. Le ticket d'entrée est plus bas que ce que les gens pensent.

Pas envie du terminal ? L'option Claude Desktop

Anthropic a sorti en avril 2026 une application Claude Desktop (Mac + Windows) avec un onglet Code intégré, zéro commande à taper. Même puissance, interface fenêtrée. Télécharge sur claude.com/download — et reviens ici pour le CLAUDE.md et les skills.

— Le shift

Pourquoi Claude Code
change tout.

L'idée centrale

Avec Claude Code, l'IA n'est plus un assistant qui suggère, c'est un agent qui exécute. C'est le passage du copilote au pilote automatique sous contrôle. Tu donnes une intention, Claude la décompose, lance les bons outils, vérifie le résultat, te rend un travail livré.

Pendant des années, l'IA pour le code, c'était de l'autocomplete : tu tapes une fonction, l'IA propose la suite, tu valides. Utile, mais tu restes le pilote. Claude Code casse ce schéma. Tu lui décris ce que tu veux obtenir, il choisit lui-même les fichiers à toucher, les commandes à lancer, les tests à faire. Tu redeviens le décideur, pas l'exécutant. C'est ce que j'appelle un workflow agentique.

Ce que ça change pour moi, concrètement

J'ai monté ce site sans écrire une ligne de HTML moi-même. J'ai construit un outil de vente qui me sert au quotidien. J'ai un Hermes Agent qui m'envoie automatiquement des messages Telegram quand mes builds passent. J'ai lancé un agent Gmail qui filtre mes emails. Tout ça, c'est Claude Code qui l'a construit, et qui le maintient.

Les vraies forces de Claude Code

  • Il lit ton codebase entier. Avec 1 million de tokens de contexte sur Opus 4.7, il peut tenir tout un projet en tête avant d'agir.
  • Il lance des sous-agents en parallèle. Tu lui demandes d'analyser cinq documents, il en lance cinq simultanément, puis synthétise. Cinq fois plus rapide qu'un agent séquentiel.
  • Il s'intègre avec MCP. Tu peux brancher Sanity, Stripe, Telegram, ta base Postgres, ton compte Meta Ads — tout via le standard ouvert MCP.
  • Il se contrôle finement. Avec les hooks et le CLAUDE.md, tu peux empêcher Claude de toucher à certains fichiers, lui imposer des règles, déclencher des actions à des moments précis.

Ce que Claude Code fait moins bien (l'honnêteté)

Je ne vais pas te vendre Claude Code comme la solution miracle. Voici ce qu'il fait moins bien dans mon expérience : il invente parfois des fonctions de librairies qui n'existent pas (le plugin context7 règle 80 % du problème en lui donnant la doc à jour). Il sur-écrit le code en ajoutant des commentaires inutiles (le skill code-simplifier nettoie). Il perd parfois le fil sur des sessions très longues (au-delà de 500 000 tokens, je préfère ouvrir une nouvelle session). Et il ne remplace pas un vrai dev senior pour des décisions d'architecture critiques — pour ça, je demande l'avis d'un humain.

Mes cas d'usage récurrents

  • Je lui demande d'écrire mes newsletters en respectant mon ton (skill copywriting)
  • Je lui demande de construire des pages web comme celle-ci (skill landing-page-generator)
  • Je lui fais auditer la sécurité de mes projets (skill security-review)
  • Je lui fais faire de la veille (skill deep-research)
  • Je lui fais écrire et envoyer des cold emails (skill cold-email)
  • Je lui fais traiter mes audios de podcast et générer les transcripts
  • Je lui fais surveiller mes builds Vercel et m'alerter quand il y a une régression

Tout ça, c'est des skills. On verra comment les installer à l'étape 04 plus bas.

— Étape 02

Installer Claude Code.

Ouvre ton terminal (Ghostty ou Terminal), et colle cette commande : 

curl -fsSL https://claude.ai/install.sh | bash

Voici ce que tu dois voir quand ça marche

Une fois l'installation terminée et le terminal relancé, tape claude --version puis claude. Tu devrais voir exactement ça :

$ claude --version
claude 1.2.3

$ claude
Welcome to Claude Code!
Ready. Type a message.
>

Si tu vois ça, c'est gagné. Si tu vois command not found, relance ton terminal (ferme-le complètement avec Cmd+Q, rouvre-le) et retente. Dans la plupart des cas, c'est suffisant.

Pourquoi cette commande ?

Elle télécharge le script officiel d'Anthropic et l'exécute. Il installe Claude Code dans ton système. Tu peux lire le script avant de l'exécuter si ça te rassure — c'est le lien dans la commande.

01

Lance la commande

Colle-la dans ton terminal, appuie sur Entrée, attends qu'elle finisse.

02

Relance ton terminal

Ferme complètement le terminal (Cmd+Q) et rouvre-le. C'est pour que la nouvelle commande claude soit prise en compte.

03

Connecte ton compte Claude

Tape :

claude

La première fois, il te demandera de te connecter avec ton compte Anthropic. Suis les instructions à l'écran. C'est 30 secondes.

04

Teste

Crée un dossier vide sur ton bureau, ouvre-le dans le terminal et lance Claude :

mkdir ~/Desktop/test-claude
cd ~/Desktop/test-claude
claude

Demande-lui par exemple : "Crée-moi un fichier hello.txt avec 'Hello world' dedans". Tu verras qu'il le crée tout seul.

— Étape 03

Poser ton CLAUDE.md.

Le CLAUDE.md, c'est un petit fichier que Claude lit à chaque session. Tu y mets tes règles, ton style, ta stack technique. Ça évite de répéter "utilise Next.js" ou "réponds en français" à chaque fois.

Je te partage mon CLAUDE.md anonymisé comme point de départ. Tu l'ouvres, tu adaptes à ton style et ta stack, et voilà.

Télécharge mon CLAUDE.md

C'est un fichier .md de 100 lignes. Anonymisé, prêt à utiliser.

Transparence : ton email t'inscrit à ma newsletter AI Playbook (1 email/semaine sur l'IA en pratique). Désinscription en 1 clic.

01

Télécharge le fichier ci-dessus

Il va atterrir dans ton dossier ~/Downloads.

02

Crée le dossier ~/.claude et copie le fichier dedans

Dans ton terminal :

mkdir -p ~/.claude
cp ~/Downloads/CLAUDE.md ~/.claude/CLAUDE.md
03

Ouvre-le et adapte-le

Ouvre-le avec ton éditeur préféré (TextEdit, VS Code, ce que tu veux) :

Remplace les sections "Stack technique" et "Architecture Next.js" par ta vraie stack. Si tu ne sais pas quoi mettre, laisse. Tu ajusteras plus tard.

Astuce : 2 niveaux de CLAUDE.md

Tu peux avoir un ~/.claude/CLAUDE.md global (règles pour tous tes projets) + un CLAUDE.md à la racine d'un projet spécifique (règles locales). Les deux sont lus.

Quand tu demandes à Claude "écris-moi un cold email B2B", il charge automatiquement le skill cold-email et suit les règles définies dedans. Tu gagnes beaucoup de temps.

Télécharge mon pack de 26 skills

ZIP de 690 Ko. Contient tous mes skills custom + le CLAUDE.md + un README.

Transparence : ton email t'inscrit à ma newsletter AI Playbook. Désinscription 1 clic.

01

Dézippe le pack

Double-clique sur jeremy-claude-pack.zip dans ton dossier Downloads. Ça va créer un dossier jeremy-claude-pack.

02

Installe les skills

cp -R ~/Downloads/jeremy-claude-pack/skills/* ~/.claude/skills/

Vérifie que ça marche

Lance Claude Code dans un dossier :

Bravo, tu es prêt.

— Au quotidien

Comment je l'utilise
tous les jours.

Le matin — La veille

Je lance claude dans mon dossier de veille et je lui demande : "Utilise le skill deep-research pour me faire un résumé des 10 news IA les plus importantes cette semaine". Pendant qu'il travaille, je prends mon café. 10 minutes plus tard, j'ai un brief clair.

En journée — Construction

Quand j'ai besoin d'écrire une landing, un email, une page — je lance Claude Code. Il charge automatiquement le bon skill (copywriting, landing-page-generator, cold-email). Je lui donne le brief en 3 phrases, et il me produit un premier jet.

Le soir — Nettoyer le code

Avant de commit, je lui fais passer security-review sur le diff (la liste des changements faits depuis la dernière sauvegarde). En 30 secondes il me dit si j'ai laissé une clé API (la « carte d'accès » qui permet à ton code de parler à un service externe payant) traîner ou si une requête SQL est vulnérable.

Ce que je ne savais pas au début

Claude Code lance plusieurs sous-agents en parallèle (des « mini-Claude » qui bossent en même temps sur des bouts différents). Quand je lui demande "analyse ces 5 docs et synthétise", il lance 5 agents en parallèle, puis synthétise. 5× plus rapide qu'en séquentiel.

— Niveau supérieur

Les plugins officiels à connaître.

Anthropic expose plus de 140 plugins officiels sur son marketplace (le « magasin d'applications » officiel — claude.com/plugins). Un plugin, c'est un pack tout prêt de skills, commandes et agents qui s'installe en une ligne. Tu n'as rien à configurer, rien à copier à la main. Une fois installé, il est dispo dans tous tes projets.

Après plusieurs semaines de tests, voici les 6 que j'utilise. Tous ajoutent une vraie valeur pour un non-dev qui pilote des projets concrets.

Installe les 6 d'un coup

Ouvre ton terminal et colle ces 6 commandes. Moins de 30 secondes.

claude plugin install superpowers
claude plugin install context7
claude plugin install claude-md-management
claude plugin install frontend-design
claude plugin install code-review
claude plugin install code-simplifier

Puis relance Claude Code (ferme et rouvre). Les nouvelles commandes slash sont disponibles.

Ce qu'ils apportent

01

superpowers — Méthodologie de dev complète

14 skills + 3 commandes slash (les raccourcis qui commencent par /) — /brainstorm, /write-plan, /execute-plan. Force Claude à spécifier avant de coder, à faire du TDD (Test-Driven Development · « écris d'abord le test, ensuite le code »), à passer en revue. Tape /brainstorm sur une idée d'article ou de feature, tu verras la différence.

02

context7 — Docs à jour de n'importe quel framework (le « squelette » technique sur lequel un site/app est construit, ex : Next.js, React)

Un MCP server (un connecteur standardisé entre Claude et un service externe) qui fetch (télécharge) la documentation officielle à jour à la demande. Claude ne te répondra plus sur la version Next.js d'il y a 2 ans. Indispensable dès que tu touches à un framework récent (Next.js 16, Supabase, Stripe, Resend v3).

03

claude-md-management — Audit automatique de tes CLAUDE.md

Commande /revise-claude-md. Lance-la dans un projet, Claude audite ton CLAUDE.md et te propose des améliorations concrètes (ce qui manque, ce qui est obsolète, ce qui mérite d'être plus précis). Je le lance une fois par mois sur mes 5 projets principaux.

04

frontend-design — UI production-grade sans briefing verbeux

Skill qui se déclenche tout seul dès que tu travailles sur une page ou un composant. Génère des interfaces distinctes, évite les designs génériques d'IA. Utile quand tu refais une section du site ou tu crées une landing.

05

code-review — Review multi-agents avant commit

Commande /code-review. Plusieurs agents spécialisés passent sur ton diff (la liste des changements faits depuis la dernière sauvegarde) : sécurité, perf, lisibilité. Chacun filtre par confiance. Moins verbeux qu'un review humain, mais attrape les oublis bêtes.

06

code-simplifier — Nettoie ce que Claude a généré en trop

Agent qui simplifie le code récemment modifié. Utile quand Claude a écrit 400 lignes pour une fonction qui en méritait 100. Tu lui demandes "simplifie", il réduit sans casser le comportement.

Comment ça s'intègre au quotidien

Tu ne les lances pas chacun un par un. Ils se déclenchent tout seuls quand leur domaine est reconnu. Les commandes slash (/brainstorm, /revise-claude-md, /code-review) sont des outils ponctuels que tu appelles à la demande. Tout le reste est automatique.

— FAQ exhaustive

Tout ce qu'on me demande
sur Claude Code.

Vingt questions que je reçois par email ou en DM toutes les semaines. Réponses directes, en première personne, sans pose marketing.

C'est quoi Claude Code en une phrase ?

Claude Code est un outil en ligne de commande créé par Anthropic, qui transforme l'IA Claude en assistant capable d'écrire, modifier, exécuter et déboguer du code directement sur ton ordinateur. Au lieu de copier-coller du code depuis un chat, tu lui parles, et il agit dans tes fichiers.

Combien coûte Claude Code en 2026 ?

Claude Code est inclus dans l'abonnement Claude Pro à 20 $ par mois, ou Claude Max à 100 $ par mois (recommandé si tu utilises Opus 4.7 quotidiennement). Tu peux aussi l'utiliser à l'usage via une clé API Anthropic, payée au token consommé.

Pour un usage quotidien régulier, l'abonnement Pro reste l'option la plus rentable. Le Max devient intéressant dès que tu lances trois ou quatre sessions Opus par jour.

Faut-il être développeur pour utiliser Claude Code ?

Non. Je ne suis ni développeur ni codeur, et je l'utilise tous les jours pour écrire des newsletters, monter des landing pages, automatiser des tâches. Claude Code lit ton intention en français et fait le travail technique à ta place.

Tu as juste besoin de savoir ouvrir un terminal et copier-coller une commande. Si tu débloques ces deux gestes, tu débloques tout l'outil.

Claude Code vs Cursor : lequel choisir ?

Cursor est un éditeur de code (un fork de VS Code) avec autocomplete IA et chat intégré. Claude Code est un agent autonome qui exécute des tâches dans ton terminal. Si tu veux remplacer VS Code et garder le contrôle ligne par ligne, prends Cursor. Si tu veux déléguer des tâches entières à un agent qui lit, écrit et teste à ta place, prends Claude Code.

Mon usage : Claude Code en principal pour les tâches lourdes, Cursor en complément quand je veux voir le diff en direct. Les deux coûtent 20 $/mois, tu peux tester les deux.

Claude Code vs Codex (OpenAI) : quelles différences ?

Codex tourne sur les modèles GPT d'OpenAI (GPT-5 family). Claude Code tourne sur Claude Sonnet et Opus d'Anthropic. D'après mon expérience, Claude est meilleur pour comprendre un codebase existant et raisonner sur du contexte long. Codex est souvent plus rapide sur des tâches courtes et créatives.

Le choix dépend surtout de l'écosystème dans lequel tu vis déjà. Si tu es sur ChatGPT Pro, Codex CLI est inclus et tu n'as rien à ajouter. Si tu veux la qualité de raisonnement maximale, Claude Code reste mon choix.

Comment installer Claude Code ?

Une seule commande dans ton terminal : curl -fsSL https://claude.ai/install.sh | bash. Tu relances le terminal, tu tapes claude, tu te connectes à ton compte Anthropic, et c'est prêt.

Le guide complet est plus haut sur cette page, avec captures, dépannage et configuration du CLAUDE.md. Compte 20 minutes la première fois.

Sur quels systèmes d'exploitation Claude Code fonctionne-t-il ?

Claude Code fonctionne nativement sur macOS et Linux. Sur Windows, il faut passer par WSL (Windows Subsystem for Linux) — Anthropic ne propose pas encore d'exécutable natif Windows pour le CLI.

Anthropic a sorti une application Claude Desktop pour macOS et Windows qui inclut un onglet Code, sans avoir besoin du terminal. C'est la voie la plus simple si tu es sur Windows et que tu ne veux pas toucher à WSL.

Comment Claude Code gère-t-il mes secrets et fichiers .env ?

Claude Code lit le contenu des fichiers que tu lui demandes de lire. Si tu lui demandes d'ouvrir un fichier .env, il le verra.

Bonnes pratiques : ajoute .env à ton .gitignore, n'ouvre jamais explicitement le fichier dans tes prompts, et utilise le skill security-review avant chaque commit pour qu'il vérifie qu'aucune clé n'a été laissée en clair dans le code. Tu peux aussi configurer un hook qui interdit toute écriture dans les fichiers .env.

Claude Code peut-il accéder à Internet ?

Oui, via plusieurs outils intégrés. WebFetch lit une page web précise, WebSearch fait une recherche, et le plugin context7 fetch la documentation officielle des frameworks à jour.

D'après mon expérience, c'est indispensable dès que tu travailles sur une stack qui évolue vite (Next.js, Tailwind, Stripe). Sans accès à Internet, Claude risque de te répondre sur la version d'il y a 18 mois.

Claude Code peut-il travailler sur plusieurs fichiers en parallèle ?

Oui. C'est même un de ses superpouvoirs. Claude Code lance des sous-agents en parallèle quand la tâche le permet. Tu lui demandes d'analyser cinq documents, il lance cinq agents simultanément, puis synthétise. Tu lui demandes de modifier plusieurs fichiers liés, il les ouvre en parallèle.

Pour aller plus loin, lis mon article Les loops Claude Code, expliqués qui détaille la mécanique d'exécution.

Quel est le contexte token de Claude Code ?

Sonnet 4.x propose 200 000 tokens de contexte par défaut, avec une option 1 million pour les très gros projets. Opus 4 et 4.7 montent jusqu'à 1 million de tokens en standard.

Concrètement, ça veut dire que Claude Code peut lire un codebase entier de plusieurs dizaines de milliers de lignes sans perdre le fil. À titre de comparaison : ce site fait environ 50 000 tokens si on prend tous les fichiers HTML, donc il rentre en entier dans le contexte d'une seule session.

Comment utiliser MCP avec Claude Code ?

MCP (Model Context Protocol) est un standard ouvert qui permet à Claude Code de se connecter à des services externes : bases de données, Sanity, Stripe, Telegram, n'importe quel CRM.

Tu installes un MCP server (souvent un paquet npm ou Python), tu l'enregistres dans ton ~/.claude/settings.json avec ses credentials, et Claude Code peut l'appeler comme n'importe quel outil natif. Beaucoup de fournisseurs proposent maintenant un MCP server officiel.

Skills vs Slash commands : quelle différence ?

Un skill est un dossier d'instructions qui se déclenche automatiquement quand Claude reconnaît le domaine de ta demande. Exemple : le skill cold-email se charge tout seul quand tu écris « rédige un cold email B2B ».

Un slash command est un raccourci manuel que tu tapes (exemple : /brainstorm) pour lancer un workflow précis. Les skills sont automatiques, les slash commands sont volontaires. Les deux peuvent coexister : un slash command peut appeler un skill.

Comment versionner mes commandes Claude Code dans Git ?

Ton dossier ~/.claude/ contient ton CLAUDE.md global, tes skills, tes hooks et tes settings. Tu peux le suivre dans un dépôt Git privé pour partager ton setup entre plusieurs machines.

Pour un projet, le CLAUDE.md local et le dossier .claude/ vivent à la racine et sont commités avec le code. C'est ce qui permet à un nouveau collaborateur (humain ou IA) de récupérer le contexte projet sans avoir à reposer toutes les questions.

Les hooks Claude Code : à quoi ça sert ?

Les hooks sont des scripts qui se déclenchent automatiquement sur des événements précis : avant une réponse, après un tool call, à l'arrêt d'une session.

Concrètement, tu peux brancher une notification Telegram à la fin d'une tâche longue (pour que ton téléphone sonne quand le build est fini), interdire à Claude de toucher à certains fichiers sensibles, ou déclencher un audit sécurité avant chaque commit. C'est ce qui sépare un Claude Code « out of the box » d'un Claude Code adapté à ton workflow.

Claude Code en mode Plan Mode : quand l'utiliser ?

Le Plan Mode force Claude à présenter son plan d'action avant d'agir. Tu l'actives avec Shift+Tab dans une session.

C'est utile dès que la tâche dépasse trois fichiers ou touche à de la base de données. Tu valides le plan ou tu le corriges avant qu'un seul fichier ne soit touché. Mon réflexe : Plan Mode obligatoire dès qu'il y a un risque de casser quelque chose, ou que la tâche peut prendre une mauvaise direction si Claude se trompe dans son interprétation.

Peut-on lancer Claude Code dans GitHub Actions ou en CI ?

Oui. Anthropic propose une intégration GitHub Actions officielle. Tu déclenches Claude Code sur un événement (pull request, push, issue), il fait sa tâche en mode non-interactif et commit le résultat.

Pratique pour automatiser des revues de code, des audits, de la documentation, ou de la génération de release notes. Demande une clé API Anthropic stockée en secret GitHub. Pour creuser, va voir la fiche lexique GitHub Actions.

Vie privée des données : Anthropic garde-t-il mon code ?

Par défaut, Anthropic ne retient pas tes données pour entraîner ses modèles si tu es sur un compte Pro ou API. Les conversations Claude Code peuvent être stockées 30 jours pour la modération abuse, puis effacées.

Pour un usage en entreprise avec données sensibles, l'option Zero Data Retention existe sur les comptes Enterprise. Si tu travailles sur du code client confidentiel, c'est l'option à demander à ton commercial Anthropic.

Quelles sont les limites connues de Claude Code en 2026 ?

Trois limites que je rencontre régulièrement :

1. Il invente parfois des fonctions d'une librairie qui n'existent pas (utilise le plugin context7 pour lui donner la doc à jour, ça règle 80 % du problème).

2. Il a tendance à sur-écrire le code en ajoutant trop de commentaires (le skill code-simplifier corrige).

3. Il peut perdre le fil sur des sessions très longues (au-delà de 500 000 tokens, j'ouvre une nouvelle session). Plus une limite humaine : Claude Code ne remplace pas un dev senior pour des décisions d'architecture critiques.

Quel modèle Claude utiliser : Sonnet ou Opus ?

Sonnet 4.x est le modèle par défaut de Claude Code : rapide, économique, suffisant pour 90 % des tâches quotidiennes. Opus 4 ou 4.7 est plus lent mais plus précis sur le raisonnement complexe, les refactorings risqués et les architectures multi-fichiers.

Mon usage : Sonnet pour le quotidien, Opus quand j'attaque une grosse réflexion d'architecture ou un debugging difficile. Tu peux switcher de modèle en cours de session avec /model. Pour comparer en détail, va voir la page modèles IA.
