Model gateway

Un model gateway (passerelle de modèles), c'est une couche centrale qui fait passer tous tes appels d'IA par un même point : elle route les requêtes, applique tes règles, trace les usages et protège tes clés. Tu la croises dès qu'une équipe utilise plusieurs modèles et veut garder le contrôle.

— Définition

Model gateway, en clair

En clair : c'est un point de passage unique vers tous tes modèles (Claude, GPT, Gemini...), d'où tu pilotes les coûts, la sécurité et les bascules de l'un à l'autre.

Ne le confonds pas avec un modèle : ce n'est pas une IA, c'est l'aiguillage devant les IA. Dès que tu jongles avec 3 modèles ou plus, il devient quasi indispensable. Pas besoin de le coder toi-même : des outils comme OpenRouter ou LiteLLM le font déjà.

Exemple concret

Mon gateway voit tous mes appels Claude, GPT, Gemini. Je vois les coûts, je log les prompts, je bascule les modèles d'un endroit.

Pourquoi ça compte

Dès que tu utilises 3+ modèles, un gateway devient indispensable pour piloter coûts, sécurité et fallbacks.

Tu le croises dans les stacks Vercel AI Gateway, LiteLLM, OpenRouter ou les entreprises qui veulent contrôler leurs appels modèles.

À ne pas confondre

OpenRouter : OpenRouter donne accès à plusieurs modèles via une API unique, avec un changement de fournisseur plus simple.

Model fallback : Le model fallback bascule vers un autre modèle quand le premier échoue, coûte trop cher ou répond trop lentement.

Erreurs fréquentes

  • Construire un gateway maison alors qu'OpenRouter ou LiteLLM suffit.
  • Y stocker les prompts sans politique de rétention.
  • Oublier le rate limiting au niveau du gateway.

Un model gateway (passerelle de modèles) est une couche centrale qui route les appels vers plusieurs IA, applique des règles, trace les usages et protège les clés. Utile dès qu'on utilise plusieurs modèles, via des outils comme OpenRouter ou LiteLLM.
