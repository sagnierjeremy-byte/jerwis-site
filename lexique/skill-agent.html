Skill & Agent

Un skill et un agent, ce n'est pas la même chose. Un skill est une méthode réutilisable, une compétence prête à l'emploi (par exemple, savoir rédiger une synthèse éditoriale). Un agent, lui, est un système qui mène une mission de bout en bout : il planifie, utilise des outils, vérifie et continue jusqu'au résultat.

— Définition

Skill & Agent, en clair

En clair : le skill est une brique de savoir-faire ; l'agent est l'ouvrier qui enchaîne les briques pour finir un chantier. Un agent peut d'ailleurs utiliser un skill au passage.

Ne tombe pas dans le piège de tout appeler 'agent' : une simple instruction de style n'en est pas un. Et inutile de monter un agent quand un skill suffit. Tu vois les skills dans Claude Code, les agents dans des outils comme n8n ou Zapier.

Exemple concret

Un agent de veille peut utiliser un skill de synthèse éditoriale pour produire le résumé final.

Pourquoi ça compte

La confusion skill/agent fait perdre du temps quand tu veux automatiser une vraie routine.

Tu vois les skills dans Claude Code et les agents dans Codex, n8n, Zapier ou les outils de veille automatisée.

À ne pas confondre

Workflow agentique : Un workflow agentique est une suite d'étapes où l'IA planifie, utilise des outils, vérifie et continue jusqu'au résultat.

Orchestration : L'orchestration organise les étapes, outils ou agents nécessaires pour atteindre un résultat.

Erreurs fréquentes

  • Appeler agent une simple instruction de style.
  • Créer un agent alors qu'un skill suffit.
  • Laisser un agent agir sans critères d'arrêt.

Mini-checklist

  • Je vérifie d'abord si le mot désigne un concept, un outil, un risque ou une métrique.
  • Je le relie à un cas concret : Un agent de veille peut utiliser un skill de synthèse éditoriale pour produire le résumé final.
  • Je garde en tête le piège principal : Appeler agent une simple instruction de style.
